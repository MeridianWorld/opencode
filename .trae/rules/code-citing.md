# OpenCode 项目记忆 - 文档编写规范

## 文档头部信息规范

**核心要求：所有技术分析文档必须在开头注明工具名和生成时间。**

### 1.1 文档头部格式要求
```markdown
# 文档标题

**生成工具**：工具名称（如 TraeCN）
**生成时间**：YYYYMMDD日HH时MM分（如 20260402日22时00分）
**文档类型**：技术分析文档 / 架构设计文档 / 代码分析文档

---
```

### 1.2 文档头部示例
**正确示例**：
```markdown
# OpenCode LSP 处理机制深度分析

**生成工具**：TraeCN
**生成时间**：20260402日22时00分
**文档类型**：技术分析文档

---
```

**错误示例**（缺少工具和时间信息）：
```markdown
# OpenCode LSP 处理机制深度分析

---
```

## 文档代码引用注释规则

**核心要求：在编写代码相关文档时，必须附上充足的源代码块。在文档中引用代码时，必须提供详细的注释说明。**

### 1. 代码引用注释标准

#### 1.1 基本格式要求
```markdown
**代码位置**：`[文件名:行号范围](file:///完整路径)`
**功能说明**：简要描述代码的功能和作用
**技术细节**：解释关键算法、设计模式或技术实现
**上下文关联**：说明与相关代码的关联关系
```

#### 1.2 详细注释示例
**正确示例**：
```markdown
**代码位置**：`[compaction.ts:L32-L48](file:///d:/github_repo/opencode/packages/opencode/src/session/compaction.ts#L32-L48)`
**功能说明**：Token 溢出检测算法，用于判断是否需要启动摘要压缩
**技术细节**：
- 计算累计 Token 使用量：`input + output + cache.read + cache.write`
- 预留缓冲区：`min(20,000, 模型最大输出token数)`
- 触发条件：当累计 Token 数 ≥ 可用窗口时启动摘要
**上下文关联**：与 `SessionCompaction.create()` 配合使用，实现自动压缩触发
```

**错误示例**（过于简略）：
```markdown
`[compaction.ts:L32-L48](file:///d:/github_repo/opencode/packages/opencode/src/session/compaction.ts#L32-L48)`
```

### 2. 注释内容要求

#### 2.1 必须包含的要素
- **功能描述**：代码的核心功能是什么
- **技术实现**：关键算法、数据结构、设计模式
- **参数说明**：重要参数的用途和取值范围
- **返回值说明**：返回值的含义和格式
- **异常处理**：可能的错误情况和处理方式

#### 2.2 推荐包含的要素
- **性能考量**：时间复杂度、空间复杂度
- **安全考虑**：安全相关的实现细节
- **扩展性**：如何扩展或修改该代码
- **测试要点**：测试时需要关注的关键点

#### 3.1 代码块注释

### 4. 文档结构要求

#### 4.1 技术文档结构
```markdown
## 功能标题

### 实现原理
[代码引用 + 详细注释]

### 技术细节
[关键算法说明 + 代码示例]

### 使用示例
[调用方式 + 参数说明]
```

#### 4.2 架构文档结构
```markdown
## 组件名称

### 职责说明
[组件的主要职责]

### 核心接口
[关键函数/方法 + 详细注释]

### 交互关系
[与其他组件的协作关系]
```

### 5. 质量检查清单

在提交文档前，请检查以下项目：

- [ ] 所有代码引用都有详细的注释说明
- [ ] 注释内容准确反映了代码功能
- [ ] 技术细节描述清晰易懂
- [ ] 上下文关联说明完整
- [ ] 代码示例格式正确
- [ ] 文档结构层次清晰

### 6. 例外情况

以下情况可以适当简化注释：
- 非常简单的工具函数（如 getter/setter）
- 自解释性很强的代码
- 临时性的调试代码

但即使在这些情况下，也应提供基本的说明。

---

**记住：详细的代码注释是高质量技术文档的基础，有助于团队成员快速理解代码逻辑和设计意图。**
